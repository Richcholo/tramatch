# The catalogue is frozen at 100 places; coverage is reported per tier

The panel said the catalogue was too small, so it grew from 65 to 100
destinations plus 36 researched places. After that expansion we **stopped
growing it** and chose to make coverage honest rather than larger.
Automated search discovery — the only mechanism that would keep answering "the
locations are too small" — stays deferred.

A catalogue where every row carries a source someone read is worth more than a
larger one that does not, and the honest answer to "is 100 enough" is not a raw
count but **per-tier coverage**: a mid-range traveller in Benguet can see three
of the province's eight destinations, and a province-wide count hides exactly
that. The admin coverage report is therefore the standing answer to that
complaint, and it names its gaps rather than rounding them off.

Consequences: expansion is future curation work, not a code feature; coverage
is reported per budget tier everywhere, because every service filters tier by
exact match and a row under the wrong tier is invisible rather than ranked
lower; and the deferral of search discovery is now recorded in two places on
purpose, so a third deferral would have to argue against this one.
